# Подготовка данных и пайплайн транскрибирования переговоров

## 1. Сбор и предобработка мультимодальных данных
Для проведения исследования был сформирован корпус данных, в основу которого легли видеозаписи турниров по управленческой борьбе. На первичном этапе работы осуществлялся сбор и систематизация видеоматериалов, после чего производилось извлечение аудиодорожек для их последующей обработки алгоритмами автоматического распознавания речи (ASR). Итоговая выборка составила 30 переговорных поединков. Особое внимание уделялось решению проблемы диаризации спикеров, чтобы исключить путаницу при анализе реплик участникам переговоров на последующих этапах.

## 2. Промпт-инжиниринг и процесс транскрибирования
Перевод извлеченных аудиоданных в текстовый формат осуществлялся с использованием модели Whisper base, после чего была проведена идентификация говорящих с последующим сведением к ролям, затем из сырого текста были выделены описания ситуаций, роли, реплики и комментарии судей с помощью Qwen 2.5. Процесс транскрибирования регламентировался строгими критериями, обеспечивающими полноту и машиночитаемость извлекаемой информации. Согласно заданным требованиям, выходные данные структурировались в формате JSON с унифицированной иерархией (в нижнем регистре). 

В рамках транскрибирования фиксировались следующие ключевые аспекты поединков:
*   **Контекст и роли:** сохранялось полное описание ситуации (`situation`), а также распределение ролей участников (`player_1`, `player_2`) в каждом из раундов (`rounds`).
*   **Ход переговоров:** диалог разбивался на отдельные реплики (`turns`), где для каждого высказывания фиксировался порядковый номер (`turn_id`), автор реплики (`speaker`) и непосредственно текст (`text`).
*   **Судейские оценки:** детально документировались решения профессионального жюри в массиве `human_votes`, включая идентификатор судьи (`judge_id`), принадлежность к судейской коллегии (`collegia`), итоговый голос (`decision`) и текстовый комментарий с обоснованием выбора (`comment`).
*   **Результаты:** фиксировался итоговый счет поединка (`result.score`).
*   **Дата обработки:** поле `metadata.date` фиксирует дату обработки поединка.

Подобная глубокая структуризация позволила перевести неструктурированный аудиовизуальный поток в формализованный датасет, пригодный для алгоритмического анализа.

## 3. Валидация данных и обеспечение качества (QA)
Для обеспечения высокой надежности данных и минимизации фактора человеческой ошибки при разметке был разработан комплекс автоматизированного тестирования на языке Python с применением библиотеки `pydantic`. Написание автотестов было обусловлено необходимостью строгого контроля качества разнородных JSON-файлов и приведения их к единому стандарту (устранение расхождений в регистре ключей, контроль типов данных).

Разработанный QA-пайплайн осуществляет проверку по двум ключевым направлениям:
1.  **Структурная валидация:** проверка наличия всех обязательных ключей (метаданных, раундов, судейских комментариев) и соответствия типов данных утвержденной схеме (`TranscriptSchema`).
2.  **Логическая валидация:** реализация валидатора `@model_validator`, который выполняет автоматический пересчет голосов судей. Алгоритм итерируется по массиву `human_votes`, суммирует голоса, отданные за `player_1` и `player_2`, и строго сверяет полученные значения с итоговым счетом, зафиксированным в поле `result.score`. 

Внедрение данного пайплайна позволило выявить и автоматически блокировать интеграцию транскрипций, содержащих логические несоответствия (например, расхождения между фактическим числом голосов и заявленным счетом), гарантируя тем самым математическую точность датасета.

## 4. Значение этапа для исследовательского вопроса
Качественно подготовленные, структурированные и прошедшие строгую автоматизированную валидацию данные формируют надежный фундамент исследования. Устранение шумов разметки и обеспечение стопроцентной консистентности судейских оценок в обучающей выборке критически важно для корректного ответа на главный исследовательский вопрос. Только на основе верифицированных транскрипций возможно объективно сопоставить степень согласованности оценок, генерируемых LLM и Decision-моделями, с эталонными решениями профессиональных судей, исключив влияние артефактов данных на итоговые метрики качества.
