## Структура разделов статьи

### 1. Title & Abstract (Заголовок и аннотация)
**Что должно войти:**
- Заголовок: краткий, информативный (например, "Evaluating Managerial Negotiations with LLMs: A Comparative Study with Professional Judges")
- Аннотация: 150 слов, структурированная (контекст → проблема → методология → результаты → выводы)
- Ключевые слова: 5–7 терминов (LLM-as-a-Judge, managerial negotiations, automated evaluation, professional judging, dialogue analysis)

**Какие данные нужны:**
- Готовая аннотация (уже есть на русском и английском)
- Финальная версия заголовка

---

### 2. Introduction (Введение)
**Что должно войти:**
- **Контекст:** Рост использования LLM для автоматической оценки текстов и диалогов (LLM-as-a-Judge парадигма)
- **Проблема:** Существующие работы оценивают общие чат-боты или экспериментальные переговоры, но не реальные управленческие переговоры по профессиональным критериям
- **Исследовательский вопрос:** Какова степень согласованности оценок LLM и Decision-моделей с решениями профессиональных судей?
- **Вклад работы:** 
  1. Многокритериальное оценивание управленческих переговоров по профессиональным критериям
  2. Прямое сравнение LLM и Decision-моделей между собой и с профессиональными судьями
  3. Анализ согласованности по отдельным критериям
- **Структура статьи:** Краткое описание разделов

**Какие данные нужны:**
- Статистика по использованию LLM в оценке (из Zheng et al., Liu et al.)
- Описание проблемы из Kwon et al. (сложности с субъективными аспектами переговоров)
- Формулировка исследовательского вопроса и гипотез (из `research_concept.md`)

### 3. Related Work (Обзор литературы)
**Что должно войти:**

- **Исследовательский пробел:** Отсутствие работ по оцениванию реальных управленческих переговоров с профессиональными судьями

**Какие данные нужны:**

### 4. Methodology / Experimental Design (Методология)
**Что должно войти:**
- **Общая схема эксперимента:** 
  1. Сбор транскриптов управленческих переговоров
  2. Формализация профессиональных критериев судейства
  3. Оценивание транскриптов с помощью LLM и Decision-моделей
  4. Оценивание тех же транскриптов профессиональными судьями
  5. Сравнение модельных и экспертных оценок
- **Дизайн эксперимента:**
  - Независимые переменные: используемый подход или модель (LLM / Decision-модель) и, при необходимости, конфигурация оценивания
  - Зависимые переменные: согласованность с профессиональными судьями (по метрикам)
  - Контролируемые переменные: длина транскриптов, предметная область переговоров
- **Гипотезы:** H1, H2, H3 (из `research_concept.md`)

**Какие данные нужны:**
- Описание профессиональных критериев судейства (сколько критериев, какие шкалы)
- Описание транскриптов (сколько, из какой области, как анонимизированы)
- Описание моделей (какие LLM, какие Decision-модели)
- Описание используемых промптов и конфигураций оценивания

**Кто предоставляет:**
- Команда Данные — транскрипты, критерии и шкалы профессионального судейства, информацию о судьях
- Команда ИИ — описание моделей, промптов и конфигураций оценивания
- Команда Статья — исследовательский вопрос, гипотезы и итоговое описание методологии

### 6. Models & Approaches (Модели и подходы)
**Что должно войти:**
- **LLM-подходы:**
  - Модели: GPT-4, GPT-3.5-Turbo, Claude, возможно открытые модели (LLaMA)
  - Промптинг: zero-shot, few-shot, Chain-of-Thought
  - Формат вывода: pairwise comparison, single-answer grading, multi-criteria scoring
- **Decision-модели:**
  - Конкретный тип и архитектура Decision-моделей уточняются у команды ИИ
  - Описание входных данных, процедуры принятия решения и формата выходной оценки
  - Условия обучения или настройки модели, если применимо
  - Формат вывода: аналогично LLM
- **Базовая линия (baseline):**
  - Определяется после пилота в зависимости от используемых моделей и доступных данных
  - Возможный baseline должен позволять оценить, действительно ли сложные модели превосходят более простой подход

**Какие данные нужны:**
- Точный список LLM и их версий
- Точный список Decision-моделей (от Подгруппы 2)
- Детали промптов (примеры в Appendix)
- Детали обучения Decision-моделей

**Кто предоставляет:**
- Команда ИИ — список моделей, их версии, настройки, промпты и описание Decision-подхода

### 7. Evaluation Metrics (Метрики оценки)
**Что должно войти:**
- **Согласованность с профессиональными судьями:**
  - Метрики согласованности выбираются после определения типа шкал и структуры экспертных оценок
  - Для числовых или порядковых шкал могут использоваться Pearson/Spearman
  - Для категориальных оценок — Cohen's kappa или другие коэффициенты согласия
  - При наличии нескольких судей отдельно оценивается human-human agreement
- **Анализ по критериям:**
  - Согласованность по каждому критерию отдельно
  - Выявление критериев, по которым модели работают лучше/хуже
- **Анализ bias:**
  - Position bias (если применимо)
  - Verbosity bias (корреляция длины транскрипта с оценкой)
- **Статистическая значимость:**
  - p-values для сравнений
  - Доверительные интервалы

**Какие данные нужны:**
- Финальный список метрик
- Формулы для расчета (если нестандартные)
- Пороги значимости (например: p < 0.05)

---

### 8. Results (Результаты)
**Что должно войти:**
- **Общая согласованность:**
  - Таблица: agreement rate, Cohen's kappa, Spearman correlation для каждой модели
  - Сравнение LLM vs Decision-модели vs baseline
- **Согласованность по критериям:**
  - Таблица или график: согласованность по каждому критерию
  - Выявление "сильных" и "слабых" критериев для каждой модели
- **Влияние конфигурации оценивания:**
  - Сравнение используемых моделей и конфигураций оценивания, если в эксперименте предусмотрено несколько вариантов
  - Проверка значимости выявленных различий
- **Анализ bias:**
  - Корреляция длины транскрипта с оценкой (verbosity bias)
  - Другие выявленные смещения
- **Примеры:**
  - 2–3 примера транскриптов с оценками LLM, Decision-модели и профессионального судьи
  - Анализ расхождений

**Какие данные нужны:**
- Результаты эксперимента (таблицы, графики)
- Статистический анализ (p-values, confidence intervals)
- Примеры транскриптов

**Кто предоставляет:**
- Команда ИИ — результаты прогонов моделей
- Команда Данные — эталонные оценки профессиональных судей
- Команда Статья — статистическое сопоставление и представление результатов

## Методологические вопросы, которые необходимо решить после пилота

### Вопросы по данным (для команды Данные):
1. **Достаточность объема данных:** Сколько транскриптов нужно для статистически значимых результатов?
2. **Репрезентативность:** Насколько транскрипты репрезентативны для всех типов управленческих переговоров?
3. **Качество транскриптов:** Насколько точно транскрипты передают реальные переговоры (включая невербальные аспекты)?
4. **Анонимизация:** Не теряет ли анонимизация критически важный контекст?

### Вопросы по моделям и эксперименту:
1. Какие конкретно LLM и Decision-модели использовать в основном эксперименте?
2. Какие конфигурации промптинга оставить после пилота?
3. Насколько стабильны оценки моделей при повторных запусках?
4. Следует ли оценивать каждый критерий отдельным запросом или все критерии одновременно?
5. Какой формат выхода модели обеспечивает наиболее сопоставимые с судьями оценки?

### Вопросы по оцениванию:
1. Какие метрики согласованности подходят для используемых шкал судейских оценок?
2. Как агрегировать оценки нескольких профессиональных судей?
3. Как учитывать расхождения между самими профессиональными судьями?
4. Нужен ли отдельный анализ согласованности по каждому критерию?
5. Какие статистические тесты использовать для сравнения подходов?
