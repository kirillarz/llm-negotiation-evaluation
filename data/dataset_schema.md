# Схема данных датасета транскрипций поединков (Обновленная)

Каждая транскрипция должна быть представлена в формате JSON и строго соответствовать следующей структуре (в нижнем регистре):

* `id` (строка) — Уникальный номер поединка.
* `situation` (строка) — Полное описание ситуации.
* `rounds` (массив объектов) — Раунды поединка:
  * `round_id` (число) — Номер раунда.
  * `roles` (объект) — Роли участников:
    * `player_1` (строка) — Роль первого игрока.
    * `player_2` (строка) — Роль второго игрока.
  * `turns` (массив объектов) — Реплики в раунде:
    * `turn_id` (число) — Порядковый номер реплики.
    * `speaker` (строка) — Кто говорит (`player_1` или `player_2`).
    * `text` (строка) — Текст реплики.
* `human_votes` (массив объектов) — Голосование судей:
  * `judge_id` (число) — Уникальный номер судьи.
  * `collegia` (строка) — Название коллегии.
  * `decision` (строка) — За кого отдан голос (`player_1` или `player_2`).
  * `comment` (строка) — Комментарий судьи.
* `result` (объект) — Итоги поединка:
  * `score` (объект) — Счет поединка:
    * `player_1` (число) — Количество голосов за первого игрока.
    * `player_2` (число) — Количество голосов за второго игрока.
* `metadata` (объект) — Метаданные файла:
  * `date` (строка) — Дата (YYYY-MM-DD).
  * `source_file` (строка) — Ссылка на источник.
* `schema_version` (строка) — Версия схемы (например, "1.0").
