## Автоматизированное оценивание управленческих переговоров с помощью LLM

Исследовательский проект команды студентов УрФУ, посвящённый изучению возможностей больших языковых моделей (LLM), в том числе моделей класса Decision, для автоматизированного судейства управленческих переговоров.

**Цель исследования** — определить, насколько оценки, выставляемые языковыми моделями на основе транскрипций реальных переговорных поединков, согласуются с оценками профессиональных судей, а также выявить характерные ошибки и ограничения такого подхода.

Репозиторий используется как единое хранилище исследовательских артефактов: материалов датасета, промптов, программного кода, результатов экспериментов и материалов для подготовки научной статьи.

## Запуск baseline LLM

Для запуска нужен Python 3.10–3.13 и ключ авторизации GigaChat API.

1. Создайте и активируйте виртуальное окружение, затем установите зависимости:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   ```

2. Создайте `.env` из примера и укажите в нем свой ключ авторизации:

   ```powershell
   Copy-Item .env.example .env
   ```

   Значение `GIGACHAT_CREDENTIALS` в `.env` должно содержать ваш ключ. Не добавляйте `.env` в Git.

3. Из корня репозитория выполните одну команду:

   ```powershell
   python test_run.py
   ```

Baseline выполняет три независимых вызова модели по одной и той же полной транскрипции — по одному вызову от лица каждой коллегии:

- `collegium_hire` использует `prompts/pilot/hiring.txt`;
- `collegium_send` использует `prompts/pilot/sending-to-negotiations.txt`;
- `collegium_trust` использует `prompts/pilot/trustee-of-property.txt`.

Каждый вызов возвращает только одного победителя: `player_1` или `player_2`. Итог и диагностика сохраняются в `results/pilot/test_baseline_result.json`:

```json
{
  "decisions": {
    "collegium_hire": "player_1",
    "collegium_send": "player_2",
    "collegium_trust": "player_2"
  },
  "calls": {
    "collegium_hire": {
      "run_parameters": {},
      "raw_response": "{\"winner\":\"player_1\"}",
      "parsed_json": {"winner": "player_1"},
      "status": "success",
      "error": null
    }
  }
}
```

Ошибка одного вызова не останавливает остальные: для проблемной коллегии в `decisions` записывается `null`, а в `calls` сохраняется доступная диагностика. После выполнения всех трёх вызовов результат записывается на диск, и команда завершается с ненулевым кодом, если хотя бы один вызов был неуспешным. Ошибка общей конфигурации, например отсутствие `GIGACHAT_CREDENTIALS` или неполный набор промптов, обнаруживается до обращения к API.

## Проверка датасета

Установите зависимости для разработки и запустите строгую проверку всех JSON-файлов основного датасета:

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest data/test_transcriptions.py
```

Проверяется только каталог `data/dataset`; исторический `data/pilot_dataset` в обязательную проверку не входит.

## Запуск экспериментального ноутбука

Ноутбук `src/models/Untitled13.ipynb` поддерживает два способа получения ключа GigaChat:

- в интерфейсе Google Colab сначала используется Secret `GIGACHAT_CREDENTIALS`, а входной JSON выбирается через форму загрузки;
- при локальном запуске или работе с удалённым ядром вне интерфейса Colab ключ загружается из `.env`, а JSON — из пути `INPUT_JSON_PATH` (по умолчанию `data/dataset/fub_video_transcript.json`);
- если ни Colab Secrets, ни `.env` недоступны, ноутбук запрашивает ключ через скрытое поле только для текущего сеанса.

Локальный `.env` не передаётся в удалённое ядро автоматически. Удалённая среда должна видеть репозиторий и `.env`: синхронизируйте файлы, подключите Google Drive или разместите их в рабочем каталоге ядра. Сам `.env` уже исключён из Git и не должен попадать в репозиторий.

Если удалённое ядро не видит входной JSON, четвёртая ячейка покажет виджет загрузки. Выберите JSON, дождитесь появления имени файла в виджете и повторно запустите эту же ячейку.


## Структура репозитория

```text
.
├── data/             # Датасет и материалы для его подготовки
├── prompts/          # Инструкции и критерии оценивания для LLM
├── src/              # Python-код экспериментов и анализа
├── results/          # Обезличенные результаты, таблицы и графики
├── paper/            # Материалы и ссылки для статьи
├── requirements.txt  # Зависимости Python-проекта
└── README.md          # Описание репозитория
```

### `data/`

Описание датасета, схема данных, реестр источников и скрипты обработки. [Оригинальные записи и транскрипции хранятся на Google Диске](https://drive.google.com/drive/folders/1irDhDTR8dEmfAdcoYkiMNGbttBW8zuCm?usp=sharing).

### `prompts/`

Версии инструкций и критериев оценивания для LLM.

### `src/`

Python-код для запуска моделей, обработки данных и расчёта метрик.

### `results/`

Обезличенные результаты экспериментов, итоговые таблицы и графики.

### `paper/`

Ссылка на актуальный черновик статьи и подборка похожих статей.

## Зоны ответственности

- **Команда данных** — каталог `data/` и папка исходных материалов в облаке.
- **Команда ИИ** — каталоги `src/`, `prompts/` и `results/`.
- **Команда статьи** — каталог `paper/`.
