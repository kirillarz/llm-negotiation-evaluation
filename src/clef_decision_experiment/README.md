# Эксперимент: судейство через Clef

> **Устаревший прототип.** Каталог сохранён для истории миграции и проверки
> функционального соответствия. Для нового сбора голосов используйте только
> `python -m src.run_experiment`; актуальные инструкции находятся в корневом
> `README.md`.

Python 3.9+. `main.py` передаёт полный поединок в AITunnel Decisions API через
`requests`: три отдельных решения на каждую из трёх коллегий, всего девять.
Счёт считается по `choice`, затем читаются человеческие голоса и сравниваются
победители, счёт и результаты коллегий. Вероятности используются только для анализа.

## Установка и запуск

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:AITUNNEL_API_KEY="sk-aitunnel-..."
.venv\Scripts\python main.py path/to/fight.json
```

Или скопируйте `.env.example` в `.env` рядом с `main.py` и укажите настоящий ключ.
Переменная окружения имеет приоритет над `.env`. Не публикуйте ключ.
При установленных зависимостях достаточно `python main.py path/to/fight.json`.
Linux/macOS: `export AITUNNEL_API_KEY="sk-aitunnel-..."`.

## Данные и регламент

Fight JSON можно хранить в любой папке; путь передаётся первым аргументом.
Обязательны строка `situation`, непустой список `rounds`, в каждом раунде
`round_id`, `roles` со строками `player_1`/`player_2`, непустой `turns`.
Каждая реплика содержит `turn_id`, `speaker` (`player_1` или `player_2`) и `text`.
Идентификаторы раундов и реплик — числа или строки. `id` используется в имени результата;
если отсутствует, используется имя входного файла.

После девяти решений ожидается `human_votes`: ровно девять объектов, по три
на коллегию, с полями `collegia` и `decision`. Например:

```json
{"collegia": "hiring", "decision": "player_1"}
```

Допустимые коллегии: `hiring`, `negotiation`, `ownership`.
Также поддерживаются русские названия «Нанимающаяся/Нанимающиеся на работу»,
«Отправляющая/Отправляющие на переговоры», «Доверяющая/Доверяющие собственность».
Человеческие комментарии и `result.score` в оценке Clef не используются.
После каждого ответа в терминал выводятся выбор судьи и P(player_1)/P(player_2).

Источник инструкций — существующий файл `judging_system (1).md` рядом с `main.py`,
раздел 2.2, приложение А и подробные критерии Б.3. Это предоставленная сводка
методики. Без файла программа завершается до запросов. Инструкции зафиксированы
в `COLLEGIA_INSTRUCTIONS`; при изменении критериев источника обновите и их.

В новый `state` входят только `situation`, все раунды с `round_id`, роли игроков
и все реплики с `turn_id`, `speaker`, полным `text`. Дополнительные поля исключены
на всех этих уровнях, исходный объект не изменяется. Проверка сериализованного
state запрещает подстроку `human_votes` (включая текст) и JSON-ключ `result`.
Текст ситуации и реплик считается исходной стенограммой: встроенные в него
человеческие оценки необходимо удалить из входных данных самостоятельно.
Текст не сокращается и не пересказывается; в API передаётся JSON-объект.

## Результат и ошибки

`results/<fight_id>_clef.json` содержит девять нормализованных голосов, полные
raw responses, `model` и `id` ответов при наличии, счёт Clef, человеческий счёт,
сравнения по коллегиям, средние вероятности, разницу счёта (Clef минус люди),
общую стоимость в рублях и сумму input_tokens. Повторный запуск с тем же id
перезаписывает файл. Отсутствующие поля API не подставляются; неполные общие
суммы равны `null`, отдельно указаны сумма доступных значений и число образцов.
Для средних вероятностей также указано число доступных образцов.
При неверной human-разметке все девять ответов сохраняются с `comparison_error`,
программа завершается с кодом 1. Ошибка API останавливает эксперимент; неполная
серия не сохраняется как успешный результат.

В норме выполняется девять HTTP POST. Для 429 и 5xx разрешены до трёх попыток
на голос с паузой две секунды: при ошибках фактических HTTP-вызовов может быть
больше девяти. Прочие ошибки, включая timeout, завершают работу без повторов.
Запуск CLI выполняет платные запросы; офлайн режима в CLI нет.

## Ограничение контекста

Перед запросами выводится размер state в символах. `usage.input_tokens`
проверяется после первого и следующих ответов: значение >= 65536 останавливает
эксперимент, отсутствие значения вызывает предупреждение после первого ответа.
Ошибки контекста API показываются без попыток сокращать стенограмму.

У AITunnel есть противоречивые указания: [страница Clef](https://aitunnel.ru/models/clef)
заявляет контекст 65 536, а [документация Decisions](https://aitunnel.ru/docs/decisions)
говорит, что Clef читает примерно первые 2K токенов state. Полная отправка и
usage.input_tokens сами по себе не доказывают, что модель учла весь поединок.
Перед интерпретацией результатов длинных поединков уточните поведение у провайдера.
