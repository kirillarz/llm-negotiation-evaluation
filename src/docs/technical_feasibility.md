# Техническая реализуемость запуска Decision Models

> **Статус:** черновик  
> **Дедлайн технического пилота:** 11 октября 2026  
> **Университетский сервер:** характеристики запрошены

## 1. Цель

Оценить технические и финансовые варианты запуска Decision Models для экспериментов на русскоязычных транскрипциях.

Рассматриваются четыре основных способа запуска:

- локальные компьютеры участников команды;
- университетский сервер;
- API разработчиков моделей;
- облачные GPU-платформы.

## 4. Возможные способы запуска

| Способ | Преимущества | Ограничения | Предварительный статус |
|---|---|---|---|
| Локальный запуск | Нет расходов на API или аренду, данные остаются локально | Ограниченный VRAM, возможные проблемы совместимости | Подходит для небольших/квантованных моделей |

### Предварительная оценка по локальному запуску

Из выбранных моделей локально наиболее реалистично протестировать **Strands Decider 2B**.

**Clef-Flash 9B** имеет открытые веса, однако в BF16 она превышает возможности доступных локальных GPU. Квантизация потенциально может сделать запуск возможным на Apple M4 16 GB, но это следует рассматривать как отдельный эксперимент, а не как основной сценарий.

**Clef 27B** для текущей локальной инфраструктуры слишком тяжёлая.

**GLiDE, Jev и OpenAI Decisions API** не требуют локального GPU, так как используются через внешние API.

## 6. Финансовая оценка

На текущем этапе можно оценить прямые расходы на inference. Итоговая стоимость полного эксперимента будет зависеть от числа транскрипций и их средней длины.

| Модель / вариант | Способ запуска | Предварительная стоимость | Комментарий |
|---|---|---:|---|
| **Clef-Flash 9B** | Cloudflare Workers AI | **$0.09 / 1M входных токенов** | Один из самых дешёвых API-вариантов. При локальном запуске отдельной платы за модель нет. |
| **Clef 27B** | Cloudflare Workers AI | **$0.24 / 1M входных токенов** | API, вероятно, экономически проще аренды 80 GB GPU для небольшого исследовательского датасета. |
| **GLiDE** | Fastino API | **ориентировочно $0.30 / 1M входных токенов** | Перед экспериментом необходимо повторно проверить актуальный тариф Fastino. |
| **Strands Decider 2B** | Локально | **$0 за API** | Основные затраты — доступное железо и время вычислений. При использовании собственного ПК дополнительных расходов практически нет. |
| **Jev** | TypeSafe API | **$0.042 / 1M входных токенов**, output не тарифицируется отдельно | Самый дешёвый из рассматриваемых закрытых API по опубликованному тарифу. |
| **OpenAI Decisions API / GPT-6 Luna** | OpenAI API | **ориентир: $0.10 / 1M input и $0.50 / 1M output** | Необходимо отдельно проверить фактический биллинг endpoint `/v1/decisions` перед расчётом полного бюджета. |

### Сравнение вариантов по затратам

Для небольшого пилота API-варианты выглядят финансово предпочтительнее аренды мощной GPU, особенно для Clef 27B.

Локальный запуск Strands Decider 2B практически не требует прямых финансовых затрат и поэтому является удобным вариантом для первого технического теста.

Аренду облачной GPU имеет смысл рассматривать прежде всего в случаях, когда:

- необходимо исследовать именно open-weight версию модели;
- университетский сервер недоступен;
- использование внешнего API невозможно из-за требований к данным;
- требуется сравнить локальный и hosted inference.

## 7. Технические ограничения и риски

Основные риски, которые необходимо учитывать:

- недостаток VRAM;
- несовместимость модели с доступным runtime;
- необходимость квантизации;
- увеличение потребления памяти при длинных транскрипциях;
- ограничения максимальной длины контекста;
- возможные проблемы с поддержкой русского языка;
- ограничения внешних API;
- требования к конфиденциальности транскрипций;
- недоступность или недостаточная мощность университетского сервера.

## 8. Предварительная схема проведения экспериментов

### Предпочтительный вариант

**Университетский сервер**, если его характеристики подходят для выбранных моделей.

### Резервный вариант 1

**Официальный API модели**, если:

- веса закрыты;
- локальный запуск технически сложен;
- необходимо быстро выполнить пилот.

### Резервный вариант 2

**Облачная GPU**, если:

- модель имеет открытые веса;
- университетский сервер недоступен или недостаточно мощный;
- локального оборудования команды недостаточно.

### Локальный запуск

Использовать для:

- разработки экспериментального пайплайна;
- первоначальных тестов;
- небольших или квантованных моделей;
- проверки корректности входных и выходных данных.

## 9. План технического пилота до 11 октября

Поскольку на университетский сервер нельзя рассчитывать, пилот строится вокруг двух основных способов запуска:

1. **локальный запуск** небольшой open-weight модели;
2. **API / managed inference** для более тяжёлых или закрытых моделей.

Облачная GPU рассматривается только как резервный вариант, если потребуется проверить open-weight модель, которая не помещается на локальном оборудовании.

### Этап 1. Подготовка среды

Выбрать две модели для первого пилота:

- одну модель, которую можно запустить локально, например **Strands Decider 2B**;
- одну модель с доступом через API, например **Clef-Flash через Workers AI, Jev, GLiDE или OpenAI Decisions API**.

Подготовить:

- единый формат входных данных;
- одинаковый набор вопросов / вариантов решения;
- 5–10 коротких русскоязычных транскрипций или их фрагментов;
- небольшой скрипт, который отправляет запрос модели и сохраняет результат.

### Этап 2. Локальный smoke-test

Запустить локальную модель на наиболее подходящем доступном устройстве:

- в первую очередь **RTX 4050 Laptop 6 GB**;
- при необходимости проверить **Apple M4 16 GB** как альтернативу.

Зафиксировать:

- удалось ли установить runtime;
- запускается ли модель без ошибок;
- фактическое потребление VRAM / RAM;
- среднее время обработки одного примера;
- ограничения по длине входного текста;
- корректность формата decision-ответа;
- базовую адекватность работы с русским языком.

Если модель не помещается в память, проверить доступную официальную или совместимую квантованную версию. Если запуск остаётся нестабильным, локальный вариант не использовать как основной.

### Этап 3. API-пилот

Провести тот же тест через одну из API-моделей.

Использовать тот же набор транскрипций и тот же набор вариантов решений, чтобы результаты можно было сравнивать.

Зафиксировать:

- успешность запросов;
- latency;
- ограничения на размер входа;
- формат результата;
- качество работы с русским текстом;
- число входных токенов;
- ориентировочную стоимость одного запроса и полного прогона датасета.

### Этап 5. Решение по основной среде

По результатам пилота определить:

- **основной способ запуска** для полного эксперимента;
- **резервный способ запуска**;
- какие модели можно использовать локально;
- какие модели целесообразнее использовать только через API;
- нужна ли аренда облачной GPU.

### Рекомендуемая схема на текущем этапе

**Основной сценарий для пилота:**

- Strands Decider 2B — локально;
- одна из более сильных Decision Models — через официальный API.

**Резервный сценарий:**

- если локальный запуск Strands не удаётся — использовать API-модель как единственную среду пилота;
- если потребуется исследовать Clef/Clef-Flash именно с открытыми весами — арендовать облачную GPU подходящего размера на несколько часов.

Облачную GPU не рекомендуется арендовать заранее: для первого пилота API и доступного локального железа достаточно, чтобы проверить весь экспериментальный пайплайн.

### Критерий успешного пилота

Пилот считается успешным, если:

- хотя бы одна Decision Model стабильно обрабатывает русскоязычные примеры;
- получен воспроизводимый структурированный decision-результат;
- измерены latency и потребление ресурсов либо стоимость API;
- понятны ограничения по длине транскрипций;
- выбран основной способ запуска и определён рабочий резервный вариант.
